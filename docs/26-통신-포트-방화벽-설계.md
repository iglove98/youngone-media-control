# 통신 포트·방화벽 설계

Agent는 수신 포트를 열지 않고 모든 업무 통신을 outbound HTTPS로 시작한다.

| 출발 | 목적 | 포트/프로토콜 | 용도 | 통제 |
|---|---|---|---|---|
| Agent | LB/AP | TCP 443 HTTPS/mTLS | 등록, Heartbeat, 정책, 이벤트, 업데이트 메타 | 서버 allowlist, TLS 1.2+ |
| 관리자 PC | LB/AP | TCP 443 HTTPS | 콘솔/API | VPN/관리자망+MFA |
| LB | AP | TCP 8080 또는 8443 | 내부 프록시 | LB 보안그룹만 |
| AP | MariaDB | TCP 3306 TLS | 업무·감사 DB | AP 서비스계정만 |
| AP | File/Object | TCP 443 | 증적·내보내기·배포물 | 전용 계정/키 |
| AP | IdP | TCP 443 | SSO/MFA | 목적지 고정 |
| Agent/AP | 내부 DNS | UDP/TCP 53 | 이름해석 | 내부 DNS만 |
| Agent/AP | 내부 NTP | UDP 123 | 시각동기화 | 내부 NTP만 |
| Monitoring | AP | TCP 8443 또는 내부 관리포트 | health/metrics | 모니터링망만 |
| Backup | DB/File | 제품별 제한 포트 | 백업/복구 | 백업망만 |

금지: Agent inbound 포트, Agent→DB 3306, Agent→SMB 445, 인터넷 임의 목적지, 운영 Swagger/Actuator 외부 공개. 프록시 환경에서는 Windows 시스템 프록시 또는 서명된 Agent 설정을 사용하고 사용자 환경변수 `HTTP_PROXY`를 신뢰하지 않는다.

## 온라인/오프라인 판정

Heartbeat 기본 60초+jitter를 시작값으로 하며 3회 누락 시 서버는 OFFLINE으로 표시한다. 대규모 VDI 로그인 폭주를 피하기 위해 최대 20% jitter와 지수백오프를 사용한다. 서버 응답 성공과 정책/로그 채널 정상 여부를 별도 상태로 기록해 `ONLINE_BUT_DEGRADED`를 표현한다.

## 서버 장애 시

DNS/LB/AP/DB/File 장애를 구분해 telemetry reason code를 기록한다. DB 장애 시 AP는 성공 수신으로 응답하지 않는다. File 장애는 Heartbeat/정책 메타데이터 경로와 격리한다. Agent는 429 `Retry-After`, 5xx 재시도, 401/403 자격증명 재등록 절차, 인증서 만료 임박 경보를 처리한다.
