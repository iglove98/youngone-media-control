# 인사·디렉터리 다중연동 설계

기준일: 2026-09-04

## 목표

고객사마다 다른 인사·계정 시스템을 교체 가능한 Connector로 지원하고 모든 입력을 하나의 내부 사용자 UUID로 정규화한다. 매체 정책·위험 이벤트·소명은 mutable한 사번이나 로그인 이름이 아니라 내부 `personId`를 참조한다.

## 지원 방식

| Connector | 대표 용도 | 동기화 방식 |
|---|---|---|
| Active Directory/LDAP | 사내 Windows 도메인, SID·UPN·그룹 | Full + DirSync/USN 등 Delta adapter |
| SCIM 2.0 | IdP·클라우드 디렉터리 | Pull 또는 inbound provisioning |
| REST API | 고객사 HR·그룹웨어 | Cursor/updatedAt delta |
| JDBC View | Oracle, MariaDB, PostgreSQL, MSSQL HR View | read-only timestamp/keyset delta |
| CSV/SFTP | 폐쇄망·레거시 ERP | 암호화 파일 batch |
| Message Queue | Kafka/RabbitMQ 등 인사 이벤트 | event-driven |
| 수동 업로드 | 초기 구축·긴급 보정 | 승인된 CSV template |

Connector 구현은 `HrConnector` 인터페이스를 따르고 비밀은 설정 JSON이나 DB에 원문 저장하지 않고 `secretRef`로 Vault/KMS/운영 비밀 저장소를 참조한다.

## 내부 사용자 모델

- `personId`: YoungOne 내부 UUID, 정책과 로그의 기준키
- `authoritativePersonKey`: 인사 원천의 변경 불가 사용자 키
- `employeeNumber`: 표시·검색용 사번, 재사용 가능하므로 기준키 금지
- `loginId`, `windowsSid`, `upn`, `email`: 로그인 상관관계 값
- `employmentStatus`: PRE_HIRE, ACTIVE, LEAVE, SUSPENDED, TERMINATED, UNKNOWN
- 조직, 관리자, 유효기간, 외부 그룹
- `externalIdentity`: 원천별 externalObjectId와 내부 personId 연결

Agent는 현재 로그인 Windows SID와 UPN을 보고한다. 서버가 이를 내부 personId에 매핑하고, Agent에 내려가는 정책에는 필요한 내부 사용자 UUID와 최소 선택자만 포함한다.

## 권위 원천과 병합

필드별 권위 원천을 설정할 수 있어야 한다. 예:

- 재직상태·사번·조직·관리자: HR REST/JDBC
- SID·UPN·보안그룹: AD/LDAP
- 이메일·클라우드 그룹: SCIM IdP
- 수동 보정: 만료시간과 승인자를 가진 override

`authorityRank`가 높은 원천이 해당 필드의 기준이지만 값이 비었다고 낮은 원천 값을 즉시 삭제하지 않는다. Field mapping과 null semantics를 원천별로 설정한다.

## 전체·증분·이벤트 동기화

- FULL: 초기 구축, 정기 대조, 누락 복구
- DELTA: cursor, 변경시각, USN, version 등으로 변경분만 처리
- EVENT_DRIVEN: 입사·이동·휴직·퇴사 이벤트 즉시 반영

모든 실행은 `hr_sync_runs`에 cursor 전후, 읽음/적용/충돌 건수, 오류를 남긴다. cursor는 데이터 적용 트랜잭션 성공 후에만 전진한다. 동일 sourceVersion/payloadHash 재수신은 멱등 처리한다.

## 퇴사·휴직 안전 처리

- TERMINATED/SUSPENDED 이벤트는 일반 변경보다 높은 우선순위로 즉시 처리
- 사용자 정책과 예외는 비활성화하되 과거 로그 참조는 보존
- 단말 기본 정책은 유지되어 사용자가 없어도 매체제어가 풀리지 않음
- Full sync에서 사용자가 사라졌다는 이유만으로 즉시 퇴사 처리하지 않음
- 원천별 missing grace 기간과 2회 이상 연속 누락 조건 적용
- 대량 퇴사/조직 삭제 임계치 초과 시 자동 적용 중지와 관리자 승인

## 충돌 및 수동 검토

다음은 자동 병합하지 않고 `hr_identity_conflicts`에 등록한다.

- 동일 externalObjectId가 다른 immutablePersonKey로 변경
- 동일 immutablePersonKey에 복수 내부 사용자
- 사번 재사용
- 같은 SID/UPN이 여러 활성 사용자에게 연결
- source 간 재직상태 충돌
- 순환 관리자 관계
- 존재하지 않는 조직·그룹 참조
- delta cursor 역행 또는 sourceVersion 역행
- 한 번의 동기화에서 비활성화 비율이 안전 임계치를 초과

충돌 해결에는 담당자, 사유, 변경 전후, 해결시각을 감사한다. 내부 personId 병합은 별도의 고위험 승인 기능으로 처리하고 자동 수행하지 않는다.

## 그룹과 정책

정책 대상은 다음을 지원한다.

- PERSON: 내부 personId
- USER_GROUP: 내부 정규화 그룹 UUID
- ORGANIZATION: 정규화 조직 UUID
- AGENT/DEVICE_GROUP
- 사용자+Agent+USB 예외 조합

그룹 중첩은 cycle을 탐지하고 최대 깊이를 제한한다. 정책 snapshot에는 계산 당시 membershipVersion을 기록하여 나중에 왜 정책이 적용됐는지 재현할 수 있어야 한다. 정책 우선순위는 긴급차단, 금지 USB, 승인 예외, 사용자+단말, 사용자, 단말, 그룹, 조직, 전역 순서를 따른다.

## 보안·개인정보

- Connector 계정은 read-only와 최소 속성 접근
- JDBC는 전용 View와 SELECT 전용 계정
- LDAP은 LDAPS, REST/SCIM은 TLS와 OAuth2/mTLS 등 고객사 방식
- CSV/SFTP는 전용 계정, host key pinning, 파일 암호화·서명, 처리 후 보존정책
- 주민번호·급여·주소·전화번호 등 매체제어에 불필요한 인사정보 수집 금지
- raw payload는 기본 미보관, 필요 시 암호화·짧은 TTL·접근감사
- 수동 업로드도 실행자, 파일 hash, 적용·거부 건수를 감사

## 장애와 운영

연동 장애 시 마지막 정상 사용자·그룹 snapshot과 서명 정책을 유지한다. 연동 실패가 매체제어 해제로 이어지면 안 된다. 다음을 모니터링한다.

- source별 마지막 성공시각과 지연시간
- cursor 정체와 delta backlog
- 신규/변경/비활성/누락/충돌 건수
- 대량 변경 안전 임계치
- mapping 실패와 알 수 없는 enum
- 정책 대상 중 미해결 사용자/그룹 수
