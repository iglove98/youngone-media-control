# 38. 최초 정책 활성화와 오프라인 제어 상태

## 확정 원칙

Agent 설치만으로 차단을 시작하지 않는다. 서버가 서명한 정책을 한 번도 받지 않은 Agent는 장치 탐지, 팝업, 감사 이벤트 적재만 수행하며 제어 결정은 DETECT_ONLY다.

정상 서명 정책을 최초 수신한 시점부터 제어가 활성화된다. 이후 서버 연결이 끊겨도 마지막 정상 정책을 계속 집행한다. 사용자가 네트워크를 끊어 정책을 우회하지 못하도록 하기 위함이다.

## 상태 전이

| 현재 상태 | 조건 | Agent 동작 | 서버 표시 |
|---|---|---|---|
| 신규 설치 | 정책 미수신, 활성화 표식 없음 | 탐지만 수행 | BOOTSTRAP_DETECT_ONLY |
| 정책 활성 | 서명·Hash·버전 검증 성공 | 정책 규칙 적용 | ENFORCING 또는 DRIVER_ERROR |
| 일시 오프라인 | 유효한 캐시 존재 | 마지막 정책 유지 | ENFORCING 또는 DRIVER_ERROR |
| 정책 삭제·손상 | 과거 활성화 이력 존재 | 필수 HID 제외 fail-closed | FAILSAFE |
| 정책 만료 | 과거 활성화 이력 존재 | 필수 HID 제외 fail-closed | FAILSAFE |
| 규칙 미매칭 | 정상 정책이나 해당 장치 규칙 없음 | DETECT_ONLY | 정책 상태 유지 |

현재 실제 KMDF enforcement가 준비되지 않았으므로 정책이 있어도 서버에는 DRIVER_ERROR가 표시된다. 드라이버가 EnforcementReady=true를 반환한 뒤에만 ENFORCING으로 표시한다.

## 활성화 표식

정상 정책 설치 시 다음 두 위치에 활성화 이력을 기록한다.

- DPAPI LocalMachine으로 보호한 activation.latch
- HKLM\SOFTWARE\YoungOne\MediaControl\Agent의 ControlActivated

기존 버전에서 정책을 이미 받은 Agent는 policy.cache 존재 자체를 활성화 이력으로 간주해 업그레이드 후 정책 삭제 우회를 막는다.

## Heartbeat

Heartbeat는 다음 실제 값을 서버로 보낸다.

- 로컬 미전송 위험 이벤트 큐 건수
- 적용 정책 버전
- BOOTSTRAP_DETECT_ONLY, ENFORCING, FAILSAFE, DRIVER_ERROR

서버 V10은 control_status 컬럼을 VARCHAR(30)으로 확장한다.

## 검증

Agent/UI 전체 빌드 성공. 단위 테스트 10개 성공, 실패 0. 신규 미정책 DETECT_ONLY, 활성화 후 정책 삭제 fail-closed, 필수 HID 안전 허용을 검증했다.
