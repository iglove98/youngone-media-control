# 정책 승인·할당·단계배포·롤백

## 업무 분리

정책 작성자는 자신의 정책을 승인할 수 없다. DRAFT는 다른 관리자 승인을 거쳐 APPROVED가 되고, 승인된 정책만 할당·배포할 수 있다. 현재 `X-Admin-Id`는 임시 연결점이며 관리자 인증 모듈 도입 후 MFA 인증 Principal과 감사 ID로 대체한다.

## 대상과 우선순위

할당 대상은 GLOBAL, ORGANIZATION, USER, AGENT다. 기본 우선순위는 AGENT 400, USER 300, ORGANIZATION 200, GLOBAL 100으로 권장하고, 명시 priority가 큰 규칙을 우선한다. 동일 우선순위는 더 구체적인 대상, 이후 최신 승인 버전 순으로 결정하도록 후속 확장한다.

현재 서버 resolver는 신뢰할 조직/사용자 디렉터리 동기화가 아직 없으므로 GLOBAL과 AGENT 대상을 실제 선택에 사용한다. ORGANIZATION/USER 할당은 저장 가능하지만 디렉터리 연계 전 Agent가 스스로 주장한 조직/사용자 값으로 선택하지 않는다.

## 단계 배포

배포 비율은 1~100이다. Agent UUID의 결정적 hash bucket으로 대상 여부를 계산하여 서버 재시작·다중 AP에서도 동일 Agent가 동일 cohort에 머문다. 권장 단계는 1%→10%→30%→100%이며 각 단계에서 정책 수신율, 적용 성공률, 차단 급증, driver 오류, offline 증가를 확인한다.

## 롤백

배포는 previousPolicyId를 기록한다. 롤백 시 현재 정책을 RETIRED, 이전 정책을 ACTIVE로 복원하고 deployment를 ROLLED_BACK으로 남긴다. Agent는 ETag 변경을 감지해 이전의 서명된 버전을 받는다. 정책 downgrade는 일반적으로 거부하지만 서버가 서명한 rollback authorization이 있는 경우에만 허용하도록 Agent 실행체에서 추가 구현한다.

## API

- `POST /api/v1/policies`: 초안 작성, X-Admin-Id 필수
- `POST /api/v1/policies/{id}/approve`: 다른 관리자 승인
- `POST /api/v1/policy-assignments`: 대상/priority 할당
- `POST /api/v1/policy-deployments`: rolloutPercentage로 배포
- `POST /api/v1/policy-deployments/{id}/rollback`: 이전 정책 복구

## 후속 필수

관리자 MFA Principal 연결, 조직/사용자 디렉터리 동기화, 승인 사유/티켓, 예약 배포, 단계 확대 API, 자동 중단 임계치, Agent 적용 영수증과 정책별 성공률 집계를 추가한다.
