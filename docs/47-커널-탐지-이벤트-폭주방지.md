# 커널 탐지 이벤트 폭주 방지

## 목적

파일 복사·백신 검사·인덱싱 과정에서 동일 장치와 프로세스의 READ/WRITE 이벤트가 초당 수천 건 발생해 Agent 메모리, SQLite 큐와 서버를 압박하는 상황을 방지한다.

## 적용 규칙

- key: kernel volume + requestor process ID + major operation
- 동일 key는 1초 구간에 최초 한 건만 정책 파이프라인으로 전달한다.
- 서로 다른 프로세스 또는 READ/WRITE/EXECUTE 종류는 독립적으로 유지한다.
- key 저장소는 최대 4,096개이며 오래된 항목을 우선 제거한다.
- Composite 채널은 최대 2,048건이고 과부하 시 가장 오래된 이벤트부터 폐기한다.
- 서버 위험도는 완전히 제거되지 않은 1초 단위 지속 이벤트로 반복 시도 증가를 계속 계산할 수 있다.

## 안전성

이 기능은 사용자 모드 로그 집계이며 커널의 I/O 허용 여부를 바꾸지 않는다. 실제 차단 모드에서는 개별 I/O를 커널 정책으로 판정하므로 이 집계가 우회 수단이 되지 않는다.

## 검증

- 동일 volume/PID/operation 1초 중복 억제 테스트
- 서로 다른 PID와 operation 분리 테스트
- Agent 전체 테스트 29/29 성공
- Release 빌드 경고 0, 오류 0
