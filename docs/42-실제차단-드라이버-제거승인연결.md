# 실제 매체 차단 드라이버 구조와 표준 제거 승인 연결

## 확인 결과

현재 YoungOneMediaControl KMDF 드라이버는 Agent와 IOCTL로 정책을 교환하는 제어 장치다. USB 저장장치의 IRP 또는 파일시스템 I/O 경로에는 연결되어 있지 않다. 따라서 EnforcementReady=false가 정확한 상태이며, 정책 수신 성공을 실제 읽기·쓰기 차단 성공으로 기록하면 안 된다.

## 목표 드라이버 구성

1. Control KMDF
   - Agent의 서명 검증 완료 정책을 커널용 고정 길이 규칙으로 수신
   - 정책 세대와 상태 조회, filter driver와 공유되는 read-mostly snapshot 관리
2. Storage/PnP filter
   - USBSTOR, UASP, WPD 등 장치 인스턴스와 볼륨 GUID를 연결
   - 장치 연결/제거, VID/PID/Serial hash, bus type을 수집
   - 장치 전체 차단과 mount 허용 여부를 담당
3. File-system minifilter
   - removable volume에만 attach
   - create/read/write/set-information/section synchronization을 검사
   - 읽기 전용은 write, delete, rename, truncate, format 관련 경로를 거부
   - 실행 차단은 image section 생성 및 실행 파일 create 의도를 검사
4. Agent
   - 사용자/조직/디바이스 정책을 해석해 커널 규칙으로 컴파일
   - 팝업, 소명, 위험도, 오프라인 캐시, 서버 재전송 담당

장치 차단과 파일 단위 읽기·쓰기 통제는 한 드라이버 콜백으로 처리하지 않는다. 장치 식별과 볼륨 상관관계가 확정되지 않은 경우 탐지만 수행하며 시스템 디스크와 HID는 절대 오차단하지 않는다.

## 판정 키

커널 hot path는 문자열 JSON을 파싱하지 않는다. Agent가 MediaType, VID, PID, SerialHash, VolumeGuid, 사용자 SID, read/write/execute action, policyVersion, expiry를 정규화한 binary rule table로 전달한다. 정책 교체는 새 snapshot 검증 후 포인터 원자 교환 방식으로 수행하고 기존 snapshot은 rundown protection 종료 후 해제한다.

VDI에서는 machine identity만으로 판단하지 않는다. installationId, agentId, organizationDeviceId, VDI provider instance, 사용자 SID, bootSessionId를 구분한다. 비영구 VDI의 로컬 장치 redirection은 서버 사용자 정책과 호스트 장치 정책 중 더 제한적인 결과를 적용한다.

## 오프라인과 장애 동작

- 최초 서버 미연결: 탐지 전용
- 정상 정책 수신 이력 있음: 마지막 정상 서명 정책 유지
- 정책 손상/만료: 필수 HID와 시스템 볼륨 제외 fail-closed
- Agent 서비스 장애: 커널에 남은 마지막 정책과 expiry 적용
- filter 상태 불명: 차단 성공으로 기록하지 않고 DRIVER_ERROR
- 정책 갱신 실패: 기존 snapshot 유지, 부분 적용 금지

## 0.19.0 표준 제거 승인

WiX InstallExecuteSequence에 ValidateAndConsumeUninstallApproval을 추가했다. 전체 제거이면서 제품 업그레이드가 아닌 경우, StopServices 전에 LocalSystem으로 AgentCtl consume-uninstall-approval을 실행한다. 승인 파일이 없거나 만료·재사용 상태이면 비정상 종료하여 표준 MSI 제거를 중단한다. MajorUpgrade는 기존 제품 교체가 막히지 않도록 제외한다.

승인은 제거가 실제 완료되기 전에 소비된다. 이후 MSI가 실패하면 새 토큰을 발급해야 한다. 이는 승인 재사용보다 재발급을 택한 보수적 동작이다.

## 보안 한계

이 연결은 제어판, msiexec 등 정상 MSI 제거 경로를 보호한다. 로컬 SYSTEM, 커널 권한, 오프라인 디스크 편집, MSI DB 변조, 직접 파일 삭제까지 단독으로 차단하지 않는다. 최종 방어는 Program Files/ProgramData ACL, 서비스 SDDL, WDAC, 코드서명, BitLocker/Secure Boot, EDR 경보, 서명된 filter driver가 함께 필요하다.

## 검증 상태

Package.wxs는 XML 파싱과 Custom Action 속성, 실행 조건, publish 경로 정의를 확인했다. 이 장비에는 WiX SDK 캐시와 WDK/Visual Studio C++ Build Tools가 없어 MSI와 커널 드라이버 바이너리 빌드는 미검증이다. Agent 제품 빌드와 18개 단위 테스트는 계속 통과해야 한다.
