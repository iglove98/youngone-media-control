# 서버 초기 배포 및 Agent 연결 구성

## 제공 산출물

- `server/Dockerfile`: Java 21 다단계 빌드, non-root UID 10001 실행
- `server/.dockerignore`: Gradle 캐시·빌드 결과 제외
- `server/application-production.yml`: HTTPS 8443과 필수 환경변수
- `infra/docker-compose.yml`: Spring AP와 MariaDB 분리 네트워크
- `infra/.env.example`: 비밀값 이름 템플릿
- `infra/agent-appsettings.example.json`: Agent 연결 템플릿

## 네트워크

- Agent → AP: TCP 8443 HTTPS
- AP → MariaDB: TCP 3306, Docker internal network 전용
- MariaDB 3306은 호스트에 publish하지 않는다.
- 관리용 DB 접근은 별도 승인된 bastion 또는 운영 세션에서만 수행한다.

## 비밀값

DB app 암호, DB root 암호, Agent bootstrap token은 모두 서로 다른 32자 이상 난수로 생성한다. 정책 서명키와 제거 승인키는 서로 다른 Ed25519 key pair를 사용한다. `.env`, PKCS#12, 개인키는 저장소와 배포 ZIP에 포함하지 않는다.

정책 공개키 환경변수는 X.509 SubjectPublicKeyInfo Base64이고 Agent `PinnedPolicyPublicKey`에도 같은 값을 설정한다. 제거 승인용 Agent pin은 X.509 끝의 32-byte raw public key Base64를 사용한다.

## TLS

서버 DNS SAN이 포함된 조직 CA 발급 인증서를 PKCS#12로 준비한다. Agent PC가 발급 CA를 신뢰해야 하며 인증서 검증 우회는 허용하지 않는다. Compose 내부 health check의 `--insecure`는 컨테이너 자체 상태 확인에만 사용한다.

## 기동 전 점검

1. `.env.example`을 `.env`로 복사하고 placeholder를 전부 교체한다.
2. `infra/secrets/server-keystore.p12`를 배치한다.
3. `docker compose config`가 성공하는지 확인한다.
4. 방화벽은 Agent 대역에서 8443만 허용한다.
5. 서버와 Agent의 시간 동기화를 확인한다.
6. 기동 후 `/actuator/health`가 UP인지 확인한다.
7. Agent 한 대로 등록·Heartbeat·정책 pin 검증 후 범위를 확대한다.

## 운영 전 분리

초기 시험에서는 Compose를 사용할 수 있지만 운영에서는 AP/DB 호스트 분리, 외부 비밀관리 시스템, 정식 인증서, DB 백업 저장소, SIEM 수집 경로를 적용한다. File 역할은 AP 프로세스의 로컬 디렉터리가 아닌 별도 논리 볼륨 또는 서비스로 둔다.
